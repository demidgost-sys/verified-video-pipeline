# v0.2 evidence contract

## Engine drift

Every new master and its crash-recovery receipt contain engine schema 1. The
required fingerprint binds the numeric FFmpeg/FFprobe versions, linked runtime
versions of libavutil, libavcodec, libavformat, libavfilter, libswscale and
libswresample, render contract 2, the exact loudness profile and a synthetic
H.264/AAC canary digest. The canary uses fixed testsrc2/sine inputs, one video
thread and disabled CPU dispatch/assembly. It hashes encoded packets through
FFmpeg's SHA-256 hash muxer. It contains no recorded or personal media.

Changes to any required field invalidate prior evidence. The full version
output is hashed into informational build IDs; distribution suffixes, compiler
metadata and Linux versus Darwin labels do not independently invalidate a
build. Raw configuration lines, binary paths, hostnames and diagnostics are
never serialized. Unknown development versions and incomplete measurements
fail closed rather than silently accepting an unrecognized engine.

Build brackets rendering with engine captures. QA checks the build fingerprint
before and after decode/loudness analysis. Manifest creation, receipt promotion
and verified READY also require that fingerprint. A mismatch requires a new
workspace, explicit human plan approval and a fresh build. Existing files and
evidence are preserved. Engine drift is an integrity blocker, not an automatic
permission to overwrite or approve anything.

This is a sampled behavior contract, not a complete software inventory: an
unreported library change that affects none of the canary packets can escape
it. The canary is not a promise of identical media on every architecture, codec
build or operating system. A conservative mismatch is allowed to block reuse.
The OS and tool installation must remain trusted; simultaneous hostile
replacement of tools and evidence is outside the threat model.

## Measured loudness

`synthetic-web-loudness@1` means:

| Field | Rule |
|---|---|
| Integrated target | -16.0 LUFS |
| Tolerance | Inclusive +/-1.0 LU, so [-17.0, -15.0] |
| Maximum true peak | Inclusive -1.0 dBTP ceiling; no extra tolerance |
| Mono handling | `dual_mono=false` |
| Measurement | FFmpeg loudnorm **input** statistics on audio stream 0 |
| Output sample rate | Explicit 48000 Hz after normalization |

Render applies this versioned normalization filter. QA separately measures the
encoded AAC master, after encode rather than trusting pre-encode settings or
loudnorm output statistics. Integrated LUFS, true peak dBTP, range LU and gate
threshold LUFS are normalized to finite JSON numbers. Missing fields,
non-numbers, silence (`-inf`), multiple JSON summaries, out-of-tolerance values,
nonzero tool exits and the 120-second command timeout stop QA. No rounding
extends the acceptance boundary. The master is rehashed after measurement;
engine and master SHA-256 bindings are included in QA and the release manifest.

This profile is a synthetic web reference, not a certification of an external
platform's loudness policy. Technical loudness never replaces human listening,
content review or the explicit human approval gate. Changing any target,
tolerance, channel interpretation or measurement semantics requires a new
profile version and render contract version.

The underlying filter semantics are documented by
[FFmpeg](https://ffmpeg.org/ffmpeg-filters.html#loudnorm).

## Schema compatibility

| Object | v0.2 version | Compatibility |
|---|---|---|
| Edit plan | 1 | Same narrow human-approved trim/profile shape |
| Project state | 2 | Requires master engine and QA loudness/byte bindings |
| Build receipt | 2 | Requires engine before recovery promotion |
| Media release manifest | 2 | Engine, measured loudness and exact-byte QA binding |
| Engine record | 1 | Strict required versus informational fields |
| Software release evidence | 2 | Declares contract versions and rebuild gate |
| Status response | 1 | Response shape retained; new blockers/actions |
| WAL journal | 1 | Same durable transition protocol; carries versioned states |

State schema 1 can be read and its intact journal can be recovered, but is
reported as `LEGACY_EVIDENCE_REBUILD_REQUIRED`. It cannot issue new v0.2 build,
QA or manifest evidence. A legacy build receipt is rejected. There is no
in-place migration that fabricates measurements for old approvals. Keep the old
workspace, make a new one from reviewed source and approve again.

The historical manifest structure is retained as
[release-manifest-v1.schema.json](../schemas/release-manifest-v1.schema.json).
The current [schema](../schemas/release-manifest.schema.json) describes v2.
JSON Schema checks shape/ranges; runtime checks additionally compare engine and
master bindings and recompute the required fingerprint.

`status` remains read-only. A size-only READY inspection returns
`ENGINE_VERIFICATION_REQUIRED`, `ready=false`, `next_action=verify`. Run
`vvp status PROJECT --verify` to rehash bytes and recapture the engine. This
read path takes the fail-fast media lease while the synthetic canary runs; it
never recovers state or changes project evidence.

## Bounded reference model

The independent model in `tests/test_model.py` defines its own five-stage order
and complete durable snapshots. Seeded operations cover legal/illegal
transitions, crashes after prepare/apply, process restart, valid/stale replay,
corrupt journal hashes, external state mutation and fresh synthetic episodes.
After **every** operation it compares the full durable state and pending-WAL
presence with the implementation. Failed recovery must preserve journal bytes.
The model never renders or reads production fixtures.

PR CI on Linux and macOS uses 32 seeds x 48 operations. The weekly/manual deep
job uses 512 seeds x 128 operations, with a 15-minute job timeout. No loop is
unbounded. A failure reports the first failing seed in the selected range and
its shortest failing prefix, including the exact replay settings:

```bash
VVP_MODEL_SEED=4 VVP_MODEL_STEPS=15 python -m unittest discover -s tests -p test_model.py -v
VVP_MODEL_PROFILE=deep python -m unittest discover -s tests -p test_model.py -v
```

The explicit seed range is [0, 2^32); replay steps must be in [1, 256]. The
smallest failing prefix is not a claim of globally minimal subsequence
shrinking. Existing targeted tests still cover real FFmpeg builds, receipt
promotion, no-clobber, byte mutation, atomic writes and competing leases.

## Platform evaluation

Linux and macOS retain POSIX `fcntl.flock`, exclusive ownership markers,
directory fsync and same-filesystem hard-link promotion. No lock fallback or
overwrite-based promotion was introduced. Native Windows remains unsupported:
there is no proven mapping here for fail-fast ownership/alias checks, directory
durability and no-clobber promotion across Windows sharing/reparse semantics.
An import requiring fcntl is intentionally a POSIX boundary, not a certification
of NTFS via a Python abstraction. WSL tests exercise Linux processes; they do
not establish native Windows or every mounted-filesystem guarantee.

A future Windows implementation must pass the same competing-process,
symlink/alias, no-clobber, partial-write and crash/recovery contracts before it
can be advertised. Network/distributed filesystems and hostile local writers
remain outside this release's guarantee.
